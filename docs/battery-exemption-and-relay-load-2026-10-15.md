# 배터리 예외 및 릴레이 부하 개선 검증 — 2026-10-15

배터리 최적화 예외를 허용한 상태에서도 삼성 실행 제한과 Parsec 끊김이 재현됐다. 이후 TCP 실행 전환과 UDP 버퍼 복사를 줄인 APK를 설치했고, 휴대폰 통신 기능 검사 11개가 통과했다. 사용자가 반복 끊김으로 USB 연결을 끈 상태를 유지했다. **새 최적화 APK의 지속 USB 사용 안정성은 아직 검증하지 않았다.**

## 적용 변경

- 앱 설정에 배터리 최적화 예외 요청, 실제 적용 상태, 설정 화면을 열 수 없을 때의 안내를 추가했다. 사용자 동작으로만 시스템 화면을 열고, 앱으로 돌아오면 PowerManager에서 상태를 다시 읽는다. 사용자가 허용했으며 시스템 화이트리스트에서도 확인했다.
- TCP 양방향 복사 작업을 읽기 실행기에서 유지해 매번 기본 실행기로 돌아가는 과정을 줄였다. 쓰기 실행기는 별도로 유지하며 취소·반쪽 종료 동작을 보존했다.
- UDP association 수신 시 재사용 버퍼의 유효 길이만 최종 프레임으로 복사한다. 중간 payload 복사본을 없애고 프레임의 독립적인 데이터 소유권과 기존 형식을 유지했다.
- 기존 페어링과 서명을 유지했다. 스레드 상한, 타이머, 제조사 실행 정책 및 열 보호 설정은 변경하지 않았다. Mac 앱과 도우미 교체는 없었다.

## 남은 검증

다음 USB 사용 시 최적화 APK로 제한 진입 전 CPU 프로파일을 먼저 수집하고, 실제 전송량과 온도를 함께 기록해야 한다. 같은 부하·온도 조건에서 Parsec 및 다운로드 유지 여부를 확인하기 전까지 반복 끊김이 해결됐다고 판단하지 않는다. 최대 동시 흐름과 장시간 사용은 이번 검사 범위에 포함하지 않았다.

근거 파일은 `build/evidence/2026-10-15-battery-exemption/`에 있다. `battery-only.patch`와 `load-only.patch`는 기존 미커밋 변경과 이번 변경을 구분하기 위한 패치다.

Android의 [Doze 및 배터리 예외 문서](https://developer.android.com/training/monitoring-device-state/doze-standby)는 인터넷 접근을 제공하는 주변기기 연결 사례를 설명하지만, 예외를 모든 제조사·열 제한의 해제로 보장하지 않는다. 시스템 요청은 [Settings API](https://developer.android.com/reference/android/provider/Settings#ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS)에 따른다.
